# 성능 진단과 개선

## 절차

1. 느린 사용자 동작, 요청, 화면, 작업 또는 성능 점검 범위를 정한다. 체감은 조사 신호로 보고 병목의 증거로 취급하지 않는다.
2. 재현 가능한 환경·데이터·측정 방법으로 변경 전 기준값을 얻는다. 분포, 반복 횟수와 변동성을 고려하고 이미 있는 지표를 우선 사용한다.
3. 프로파일, trace, 쿼리 계획, 네트워크·렌더링 시간 등 해당 경로의 근거로 가장 큰 비용을 찾는다. 측정되지 않은 추측성 최적화는 피한다.
4. 병목에 한정해 수정하고 같은 조건에서 다시 측정한다. 정확성, 메모리, 비용이나 다른 경로의 악화가 없는지 관련 검증을 한다.
5. 개선이 확인되면 의미 있는 회귀 기준을 남긴다. 수치가 흔들리거나 개선이 없으면 그 결과를 밝히고 가설을 다시 검토한다.

운영 지표가 필요하면 `runtime-observability`로 계측 경계를 정한다. 프로젝트가 합의하지 않은 전역 성능 목표를 만들어 강제하지 않는다.

## 결과

측정 조건, 변경 전후 수치, 병목 근거, 수정 내용과 남은 한계를 보고한다.
