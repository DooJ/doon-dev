# 프로젝트 기능 지도 기준

기본 코드그래프의 분석 단위는 개별 화면·클래스가 아니라 **프로젝트와 주요 기능**이다. Graphify의 심볼 그래프는 구현 근거이고, Archify는 프로젝트 간 역할과 기능 연결을 보여주는 그림이며, Obsidian 멀티 볼트는 이 둘을 설명·탐색하는 파생 뷰이고, 재사용할 관계 데이터는 `data/catalog.json`에 등록한다.

여러 프로젝트의 기능·관계 입력은 [기능 지도 입력 형식](capability-map-format.md)의 `capability-map.json`으로 검증한다. 메서드·검토 흐름·계약은 [데이터·멀티 볼트 계약](data-vault-model.md)에 따라 별도 원본으로 보존한다. 에이전트가 Graphify 숫자나 개요 노드만으로 입력을 채우지 않도록, 아래 근거 수집과 대표 경계의 코드 재확인을 먼저 한다. 이 입력은 다음 실행에서 기능을 추가·수정할 수 있는 확장 지점이다.

## 근거 수집

1. 요청한 프로젝트를 하나씩 확인하고 각자의 실행 형태, 주요 책임, 제공 기능, 사용하는 기능, 외부 경계와 근거 경로를 모은다. 기능은 사용자가 얻는 결과나 시스템 운영 목적에 따라 묶는다. 화면·API·메서드는 그 기능을 증명하는 진입점이지 기본 지도의 제목이나 노트 수 목표가 아니다.
2. WAR/JAR만 있는 서버도 빈 경계로 처리하지 않는다. 아카이브의 `WEB-INF/classes`, 라우트·서비스·스케줄러·설정·MyBatis 매퍼, 메서드 호출을 조사한다. 사용 가능한 검증된 역컴파일러가 있으면 필요한 클래스를 역컴파일하여 호출·분기를 대조한다. 클래스 파일을 압축 해제한 것만으로 원본 Java 소스나 Graphify AST에 포함됐다고 주장하지 않는다. 역컴파일 결과는 원본 파일·해시·클래스·메서드와 연결하고, 주석·로컬 변수명·리플렉션·실제 운영 데이터 등 복원되지 않는 부분은 구분한다.
3. Graphify에 서버 역컴파일 코드를 입력하려면 앱 원본 코드와 서버 재구성 코드를 구분해 추출 범위·입력 경로·노드 출처를 기록한다. 서버를 Graphify에 넣지 못했다면 수동 바이트코드·설정·매퍼 분석 결과를 별도 근거로 연결하고, 전체 그래프가 서버까지 분석했다고 말하지 않는다.

## 기본 산출물

- 상위 볼트의 프로젝트 기능 지도에는 요청한 **각 프로젝트**의 역할, 주요 기능, 제공·사용하는 계약, 소스·아카이브 근거, 확인하지 못한 기능 범위를 정리한다. 주요 기능은 프로젝트별 노트에서 확장할 수 있게 안정적인 이름으로 연결한다. 상위 볼트에는 프로젝트별 로컬 대리 노트를 두고 각 상세 볼트로 이동할 수 있게 한다. 여러 프로젝트를 한 표로만 뭉쳐 역할을 생략하지 않는다.
- 상위 볼트의 기능 관계 지도에는 기능을 기준으로 관련 프로젝트의 역할을 나란히 놓는다. 관계를 `중복 구현`, `공통 기능 사용`, `생산자·전달자·소비자 연결`, `유사하지만 목적이 다름`, `확인 필요`로 구분하고 각 판단의 코드·계약 근거를 적는다. 같은 서버 API를 호출하는 앱 둘을 근거 없이 중복 구현으로 분류하지 않는다.
- 상위 볼트의 흐름 영역에는 **프로젝트 경계를 지나는 주요 기능**의 시작 프로젝트, 참여 프로젝트별 책임, 전달 계약, 최종 결과와 중요한 분기·미확인 구간을 설명한다. 각 솔루션의 상세 볼트에서는 검토한 기능의 메서드·조건·상태·실패를 내부 경로로 연결한다. 자동 색인 전체를 기계적으로 노트화하지 않는다. 기능 하나를 나중에 심화해도 다른 기능 설명을 덮어쓰지 않도록 안정적인 제목과 링크를 쓴다.
- Archify에는 프로젝트별 책임과 핵심 기능 연결을 읽을 수 있는 전체 구조도를 둔다. 하나의 구조도로 구분하기 어려운 핵심 교차 기능은 sequence·dataflow 등 별도 그림으로 보강한다. 모든 화면이나 단순 API마다 그림을 만들지 않는다.

## 완료 검사

1. 요청한 프로젝트마다 역할과 주요 기능이 있고, 기능별 제공자·사용자·공통 구현 또는 연결 상대를 찾을 수 있는지 확인한다. 빠진 프로젝트·기능군은 완료로 숨기지 않고 제외·미확인 이유를 남긴다.
2. 중복 기능 판정은 구현과 목적을 모두 대조한다. 공통 라이브러리 사용, 같은 API 소비, 유사한 화면, 진짜 중복 구현을 혼동하지 않는다.
3. 대표 교차 기능은 앱 또는 서버 진입점에서 다른 프로젝트의 처리와 결과까지 코드·바이트코드·설정 근거로 따라가 본다. 정적 확인·역컴파일 추론·운영 확인 필요 상태를 각 경계에 표시한다.
4. Graphify 노드 수, Archify 검사 통과, 볼트 링크·지문 검사는 산출물 무결성이다. 이 검사만으로 프로젝트 역할·주요 기능·중복·연결 관계의 분석 완료를 선언하지 않는다.
