# 코드그래프 개요 지도

Graphify의 원본 `graph.json`·`graph.html`은 코드 노드와 군집을 탐색하는 상세 자료다. 코드 노드가 많거나 군집명이 일반적인 경우, 프로젝트 하나만 분석해도 사람이 이해하는 구조도가 되지는 않는다. 개요 지도의 필요 여부는 저장소 개수와 **사용자가 요청한 질문을 원본 화면에서 읽을 수 있는지**를 함께 판단한다.

## 분석 단위와 지도 깊이

| 범위 | 개요 지도 기준 | 필수 연결 |
|---|---|---|
| 단일 프로젝트 | 원본 Graphify 화면에서 요청한 구성요소와 주요 흐름을 바로 찾기 어렵다면 모듈·하위 시스템·중요 진입점 수준의 개요를 만든다. 원본 화면이 이미 충분하면 개요를 중복 생성하지 않는다. | 모듈 간 의존, 핵심 데이터·제어 흐름, 외부 시스템 경계 |
| 여러 프로젝트·저장소·서비스 | 프로젝트가 한 폴더에 모여 있어도 프로젝트 경계를 먼저 식별하고, 요청 범위의 각 프로젝트가 맡는 역할·주요 기능과 연결 상대를 한 화면에서 확인할 수 있는 통합 개요를 만든다. | 프로젝트 간 기능 목적·역할·계약·방향. `HTTP API`처럼 전송 방식만 적은 엣지는 기능 관계 지도로 연결한다. |

분석 대상이 같은 Git 저장소 안의 여러 앱일 수도 있고 별도 저장소일 수도 있다. 디렉터리 수로 의미 단위를 자동 결정하지 않는다. Graphify 원본 그래프는 프로젝트 루트에서 한 번 추출하거나, 저장소마다 추출한 후 원본의 `merge-graphs`·`global` 기능을 검토할 수 있다. 어느 방법이든 노드의 소속과 소스 리비전을 추적해야 하며, 여러 그래프를 합친 것만으로 프로젝트 간 호출 관계가 증명되지는 않는다.

## 생성 계약

1. 원본 `graphify-out/graph.json`·보고서, 실제 코드·설정·기존 문서·배포 아카이브를 대조해 개요 노드와 엣지를 선택한다. 노드 ID는 재실행해도 안정적으로 유지하고 사람이 아는 이름을 `label`로 쓴다. 각 프로젝트 노드에는 역할과 주요 기능의 탐색 근거를 연결한다. 엣지에는 방향, `relation`, 기능 목적이 드러나는 짧은 `label`, 소스 경로와 확인 수준을 담는다. 한 프로젝트 쌍에 기능이 여럿이면 그림에 모두 우겨 넣지 않고 기능 관계 지도로 연결한다. `EXTRACTED`·`INFERRED`·`runtime-required`를 혼동하지 않는다. 서버 배포본의 상수 일치를 내부 호출 실행으로 승격하지 않는다.
2. 개요 그래프는 `codebase-map/<범위>/<버전>/graphify-out/overview/graph.json`에 저장한다. Graphify의 `nodes`·`links` 구조를 따르되 상세 원본과 다른 범위·버전의 결과를 덮어쓰지 않는다. 이미 만든 `component-graph.json`이 있다면 그 내용을 검증해 개요의 입력으로 재사용할 수 있다. 단순 파일 복사 뒤에도 범위와 근거·표시 이름을 다시 확인한다.
3. Graphify의 설치된 CLI가 `export html --graph`를 지원하는지 확인하고 프로젝트 루트에서 아래처럼 실행한다. 검토한 원본에서는 HTML이 입력 그래프와 같은 폴더에 `graph.html`로 생성된다. 다른 버전에서 출력 위치가 다르면 실제 동작을 확인해 같은 역할의 별도 파일로 보존한다.

```bash
SCOPE_NAME='보이미 생태계'
VERSION='v1.0.0'
graphify export html --graph "codebase-map/$SCOPE_NAME/$VERSION/graphify-out/overview/graph.json"
```

4. 해당 범위·버전의 `graphify-out/overview/graph.html`을 브라우저에서 열어 실제 표시 노드·관계와 검색을 확인한다. JSON만 만들고 HTML 또는 열람 가능한 동등한 화면이 없으면 개요 지도는 완료되지 않았다. Archify 구조도는 별도 시각 설명으로 연결한다. 같은 버전의 Graphify 원본 `graph.html`은 코드 상세 탐색 경로로 남긴다.
5. 해당 범위·버전의 `README.md`와 Obsidian `00_HOME.md`·`01_SYSTEM_MAP.md`의 기본 그래프 링크는 **같은 범위·버전의 개요 HTML**로 향하게 한다. 단일 프로젝트에서 개요가 불필요하다고 검증했을 때만 원본 HTML을 기본 링크로 쓴다. 볼트의 구성요소·흐름 노트는 개요 그래프의 현재 노드·엣지와 대조한다. 생성기가 그래프에서 수치만 읽고 관계 설명은 고정 문자열로 유지한다면 연결을 검증한 것으로 보지 않는다.
6. 기존 Graphify 자동 Obsidian 노트·Canvas가 이미 있으면 소유권을 지켜 보존하되, 새 홈에서 **원시 탐색 자료**라고 표시하고 기본 읽기 순서나 현재 구조도의 대체물로 소개하지 않는다. 안전하게 구분할 수 없는 경우 기존 파일을 이동·삭제하지 않고 혼재 사실을 보고한다.

## 완료 검사

- 단일 프로젝트: 사용자가 요청한 진입점·주요 모듈·핵심 흐름을 기본 화면에서 찾을 수 있다. 개요를 생략했다면 원본 화면으로 충분한 이유를 확인한다.
- 여러 프로젝트: 요청 범위의 각 프로젝트가 개요에 한 번 이상 나타나고, 해당 프로젝트의 역할·주요 기능과 확인된 프로젝트 간 기능 관계로 이어진다. 관계의 방향·유형·근거·미확인 부분을 볼 수 있어야 한다. 프로젝트 간 관계가 없다면 억지 연결을 만들지 않고 **확인된 연결 없음**으로 보고한다.
- 두 범위 모두: 개요 JSON의 노드·엣지 수와 HTML 표시가 맞고, 대표 관계를 원본 파일 또는 배포 근거와 대조한다. Archify·Obsidian·README가 같은 **범위·버전·기준 시점**의 지도를 가리키며, 다른 범위나 오래된 버전 경로를 최신 결과처럼 링크하지 않는다.
