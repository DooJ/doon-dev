# 독립 Obsidian 볼트 작성 기준

`codebase-map/vault/`는 프로젝트의 현재 구현을 읽고 따라갈 수 있게 만드는 탐색용 볼트다. Graphify의 그래프는 관계 근거, Archify는 핵심 구조의 시각 근거로 사용한다. 기존 보이미 볼트의 홈·시스템 지도·구성요소·흐름·상세 색인과 생성/수동 영역 분리 방식을 일반화한다. 해당 볼트의 제품별 내용이나 노트 수를 다른 프로젝트에 복제하지 않는다.

## 구성

1. `00_HOME.md`: 무엇을 분석했는지, 기준 시점·범위, 읽는 순서, 핵심 노트 링크, 확인한 사실과 남은 공백을 적는다. `codebase-map/README.md`, Graphify 그래프/보고서, Archify HTML의 상대 링크를 제공한다.
2. `01_SYSTEM_MAP.md`: 사용자가 이해할 수 있는 구성요소와 주 경로를 설명하고 필요하면 Mermaid를 넣는다. Archify 구조도로 이어지는 링크를 제공하며, 런타임 배치나 실행 성공을 정적 분석만으로 단정하지 않는다.
3. `10_Projects/` 또는 알맞은 이름의 구성요소 영역: 범위에 들어온 서비스·앱·모듈의 역할, 진입점, 입력/출력, 주요 의존성과 관련 흐름, 확인한 코드·설정·문서 근거, 미확인 사항을 적는다.
4. `60_Flows/` 또는 알맞은 흐름 영역: 실제로 중요한 사용자·데이터·제어 흐름을 시작 조건 → 단계 → 분기/실패 → 결과 순서로 설명한다. 관계 목록만 다시 쓰지 않고 어떤 일이 왜 이어지는지 설명한다. 코드가 증명하지 못하는 운영 단계는 별도로 표시한다.
5. API, DB, 프런트엔드, 코드, 기존 문서 색인은 해당 프로젝트와 요청에 필요할 때만 `20_Code/`, `30_APIs/`, `40_Frontend/`, `50_Database/`, `70_Documents/` 등에 추가한다. 기존 문서는 원본 경로를 명시하고, 볼트에 열람본을 복제할 때는 중복 관리와 민감정보를 점검한다. 문서가 없다는 이유로 사전 문서 작성을 요구하지 않는다.
6. `80_Generated/`에는 생성 범위·입력 기준·검증 결과·갱신 방법과 이 볼트 생성 과정이 소유하는 파일 목록을 둔다. `90_Manual/`과 기존 `.obsidian/` 설정은 사용자 영역으로 보존한다. 비어 있는 범주 폴더는 만들지 않는다.

## 근거와 작성 깊이

- Graphify `graph.json`과 보고서에서 범위와 연결 후보를 찾은 뒤, 핵심 주장과 흐름은 현재 코드·설정·검증된 문서로 대조한다. Graphify의 `EXTRACTED`도 런타임 검증을 뜻하지 않는다. Archify 다이어그램은 탐색 진입점으로 연결하되 다이어그램만을 코드 근거로 삼지 않는다.
- 구성요소 노트에는 역할 한 줄과 실제 책임, 주요 관계의 의미, 해당 구현 경로를 적는다. 흐름 노트에는 적어도 시작점·도착점·중간 처리와 확인 가능한 분기 또는 한계를 적는다. 출처 파일·행·리비전은 확인한 범위에서만 기록하고, 외부 배포 아카이브는 정적 확인 범위를 밝힌다.
- 검증한 사실은 `confirmed`, 정적 추론은 `inferred`, 실행 환경 확인이 필요한 부분은 `runtime-required`처럼 일관되게 표시한다. 수치와 범위는 실제 산출물에서 다시 계산한다. 사용자가 지정한 핵심 범위를 먼저 충실히 작성하고, 수천 개 노드의 기계적 Markdown 변환으로 깊이를 대신하지 않는다.
- 원본 코드의 비밀값, 토큰, 개인정보, 실행 DB 행, 로컬 절대경로와 불필요한 코드 원문은 볼트로 복제하지 않는다. 파일 경로는 가능한 프로젝트 상대경로로 적고 링크 대상이 실제 존재하는지 확인한다.

## 재실행과 기존 볼트

1. 쓰기 전에 볼트의 현재 파일과 `.graphify_obsidian_manifest.json`, `80_Generated/`의 소유권 기록을 조사한다. Graphify가 만든 노트, 사용자가 직접 고친 노트, `90_Manual/`, `.obsidian/` 설정은 이 절차가 덮어쓰거나 자동 삭제하지 않는다.
2. 새 노트와 변경안을 먼저 준비하고, 이 절차가 이전에 생성한 파일만 식별 가능한 별도 manifest에 경로와 내용 지문을 기록한다. 기존 생성 파일의 지문이 기록과 다르면 사용자 편집으로 보고 해당 파일 변경을 멈춘다. 처음 접한 기존 파일은 소유권이 불명확하므로 덮어쓰지 않는다. 노트가 많거나 반복 갱신이 예상되면 프로젝트 전용 생성기를 두고 이 검사를 자동화한다.
3. 입력에서 사라진 노트는 링크와 수동 변경 여부를 확인한 뒤 복구 가능한 보관 위치로 옮기거나 미사용 표시를 한다. 기존 Graphify 노트가 있는 볼트는 먼저 새 시작점과 설명 노트를 추가하고, 기존 노트의 정리·이동은 링크와 소유권을 검증한 별도 마이그레이션으로 다룬다.
4. `00_HOME.md`에서 핵심 흐름까지 탐색하고, Obsidian `[[wikilink]]`와 상대 파일 링크, Archify HTML 링크를 확인한다. 대표 흐름 하나 이상을 코드 근거와 대조하고, 범위·미확인 사항·갱신 방법을 사용자에게 보고한다. 볼트를 Graphify 입력에 다시 포함하지 않는다.
