# 독립 Obsidian 볼트 작성 기준

[분석 데이터와 멀티 볼트 계약](data-vault-model.md)에 따라 `<버전>/vaults/` 아래에 독립 볼트를 둔다. `vaults/` 자체는 볼트가 아니다. 상위 연결 볼트와 솔루션별 상세 볼트는 같은 데이터의 탐색 뷰이며, 검색이나 별도 화면은 `data/catalog.json`이 가리키는 JSON 원본과 안정 ID를 사용한다. 기존 단일 `vault/`는 이전 버전의 산출물로 보존한다.

## 상위 연결 볼트

- `00_HOME.md`에서 분석 범위·버전·기준 시점, 13개처럼 실제 요청 범위에 속한 모든 솔루션, 기능 관계와 주요 교차 흐름, 근거·미확인 지점으로 이동한다.
- 솔루션마다 로컬 대리 노트를 만들어 역할·제공·사용 기능·상대 솔루션·상세 볼트 이동 링크를 적는다. Obsidian의 기본 그래프는 볼트별이므로 `obsidian://` URI만으로 상위 그래프에 엣지가 생긴다고 설명하지 않는다.
- 흐름 노트는 시작 솔루션 → 계약/전달 경계 → 결과 솔루션과 주요 분기·실패를 로컬 위키링크로 잇는다. 각 연결의 방향·상태·근거를 표시한다. HTTP·MQTT·Bluetooth·Intent·DB는 해당 경계의 계약 노트로 구분한다.
- 기능 지도는 프로젝트별 역할·주요 기능과 중복·공유·협력 관계를 보여준다. Graphify 개요·Archify 구조도는 링크로 연결하되 다이어그램을 실행 증거로 삼지 않는다.

## 솔루션 상세 볼트

- `00_HOME.md`에서 자기 솔루션의 역할·기능, 검토 메서드 색인, 직접 연결 경계, 참여 흐름과 상위 볼트로 이동한다.
- 기능마다 실제 시작 메서드와 내부 경로를 붙인다. 메서드 노트에는 안정 ID, 클래스·시그니처, 소스/아카이브 위치, 들어오고 나가는 호출, 조건, 데이터 변환, 상태 변경, 오류·재시도, 부작용과 검증 지점을 확인한 만큼 기록한다. 이름만 같은 메서드를 자동 연결하지 않는다.
- 다른 솔루션 메서드나 통신 경계가 직접 닿으면 로컬 대리 노트를 둔다. 대리 노트는 소속 솔루션과 `obsidian://open` 대상, 연결 상태를 밝힌다. 본문을 중복 작성해 서로 다른 사실 원본을 만들지 않는다.
- 자동 색인의 메서드 수와 검토한 흐름·메서드 수를 모두 표시한다. 주요 기능 중 경로를 확인하지 못한 것은 누락을 숨기지 않고 미검토·미확인 목록에 둔다. 전체 메서드 수만큼 기계적으로 노트를 만들지 않는다.

## 그래프 노드 이름과 안정 ID

- Obsidian 기본 그래프의 노드 이름은 Markdown **파일명**이다. 본문의 `# 제목`이나 위키링크 별칭만 바꿔서는 그래프의 해시 노드가 읽히지 않는다. 생성 노트의 파일명은 노드를 열기 전에도 솔루션·종류·동작을 알아볼 수 있게 한다. 예: `web-POST_lite_displayOff.do.md`, `push-MQTT_LITE_DISPLAY_OFF.md`.
- 메서드·계약·흐름의 안정 ID는 JSON과 노트 본문 또는 frontmatter에 그대로 둔다. 파일명은 탐색용 표시 이름이며 데이터 결합 키로 사용하지 않는다. 이름이 겹칠 때만 읽을 수 있는 접두어 뒤에 짧은 안정 ID 해시를 붙인다. 해시만 있는 파일명은 생성하지 않는다.
- 재생성으로 파일명이 달라지면 기존 생성 노트의 소유 지문을 확인한 뒤 이동하고, 같은 볼트 위키링크·교차 볼트 URI·생성 manifest를 함께 갱신한다. `.obsidian/`은 사용자 소유이므로 기존 값을 보존한다. 열린 탭의 이전 경로가 있으면 해당 참조만 새 경로로 옮긴다.
- 검사에서는 생성된 노트에 해시만 있는 파일명이 없는지 확인하고 대표 계약·메서드·흐름이 그래프에서 식별 가능한지 읽는다. 앱 화면 확인 여부는 정적 검사와 구분한다.

## 근거와 소유권

- Graphify 상세·개요 그래프와 보고서에서 후보를 찾고 현재 코드·설정·아카이브·검증된 문서를 대조한다. Graphify `EXTRACTED`도 런타임 증거는 아니다. Archify가 별도 문서 묶음을 분석하지 않았다면 문서 분석 완료로 쓰지 않는다.
- 프로젝트 노트에는 역할 외에 주요 기능의 제공·소비 관계와 대표 구현 근거를 적는다. 흐름에는 확인한 구현, 정적 추론, 운영 확인 필요, 계약 불일치를 구분한다. 소스 파일·행이나 아카이브 내부 클래스·메서드를 가능한 범위에서 제시한다.
- 원본 코드의 비밀값·토큰·개인정보·실행 DB 행·기기 절대경로를 노트에 복제하지 않는다. 저장소 상대경로를 쓰고 링크 대상의 존재를 확인한다.
- `generation-manifest.json`이나 볼트별 소유 목록에 생성 파일과 내용 지문을 기록한다. 생성기 소유 범위 밖의 노트와 `.obsidian/` 개인 설정을 덮어쓰지 않는다. 지문이 다른 생성 노트는 사용자 편집으로 보고 갱신을 멈춘다.
- 재분석 때 새 기능·관계·검토 경로가 데이터에 들어왔는지 먼저 확인하고, 생성기가 고정된 일부 흐름만 재출력하지 않는지 검사한다. 사라진 노트는 이전 버전 링크와 보존 이유 없이 삭제하지 않는다.

## 완료 확인

`check_multi_vault.py`로 데이터 SHA-256, 볼트 등록, 요청한 솔루션 ID, 각 볼트 홈에서 생성 노트까지의 경로, 내부 위키링크, 교차 볼트 URI를 확인한다. 상위 볼트에서 대표 교차 흐름을 열어 양쪽 구현과 결과를 읽고, 솔루션 볼트에서 같은 경로의 내부 메서드·경계가 이어지는지 대조한다. 정적 검사와 Obsidian 앱 화면 확인은 구분해 보고한다. HTML 그래프는 원시 탐색이나 특정 목적의 보조 뷰로 둔다.
