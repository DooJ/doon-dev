# 스토어 배포 점검

앱별 배포 버전과 확인 근거를 연결한다. 여러 앱을 점검하면 각각의 저장소·스토어·환경·산출물을 구분한다. 이 스킬은 체크리스트를 제공하며, 호출만으로 소스 수정·Git push·키 교체·스토어 제출을 승인하지 않는다.

## 요청 범위와 설정

- `스토어 체크해`, `배포 준비해`, `출시 기록 정리해` 요청에 적용한다. 라이브러리 또는 스토어 주의사항만 요청하면 해당 범위부터 완료하고 나머지 전체 점검을 강제하지 않는다.
- 현재 요청과 앱의 기존 운영 문서에서 플랫폼, 저장소 유무, 스토어 앱 식별자, 배포 환경과 대상 버전을 확인한다. 필요한 항목만 부족할 때 질문하고 독립적으로 가능한 조회는 진행한다.
- 앱별 설정은 기존 프로젝트 문서를 우선한다. 별도 설정이 없으면 프로젝트의 `docs/app-store-release-settings.md`, 없으면 상위 작업공간에서 가장 가까운 같은 경로의 공통 설정을 참고한다. 명시된 설정 파일이 있으면 그 위치를 사용한다. 공통값보다 앱별 예외와 사용자의 최신 지시를 우선한다.
- 설정 파일을 새로 작성할 때만 [앱 설정 양식](references/app-settings-template.md)을 읽는다. 계정 자격 증명이나 실제 서명 키를 스킬·양식에 저장하지 않는다.

## 필수 원칙

- 라이브러리 갱신에 코드 또는 빌드 설정 수정이 필요하면 변경 대상·이유·영향을 **수정 전에 알린다**. 이미 승인된 작업을 다시 승인받는 절차로 바꾸지 않는다. 조회만 요청받았으면 버전을 변경하지 않는다.
- GitHub 최신 소스·머지·푸시 점검은 **레포지토리가 있는 경우** 수행한다. 저장소가 없으면 해당 없음으로 기록하고 임의로 생성하지 않는다.
- 설정 파일에 난독화나 매핑 업로드 옵션이 있다는 사실만으로 완료 처리하지 않는다. 해당 배포 산출물의 적용과 크래시 복원 근거를 확인한다.
- 완료, 조치 필요, 미확인, 해당 없음을 구분하고 확인 시각·대상 버전·근거를 남긴다. 접근 불가·미실행은 미확인, 요청 범위 밖은 범위 밖으로 표시한다.
- 정책·SDK 최신 버전·스토어 기한은 확인 시점의 공식 자료와 실제 Console을 기준으로 한다. 최신 안정 버전과 프리릴리스를 구분하고, 낮은 최적화 점수만으로 게시 차단이나 기한을 추정하지 않는다.

## 실행 흐름

전체 준비 점검에는 [필수 체크리스트](references/release-checklist.md)를 읽고 다음 순서로 진행한다. 부분 요청에는 필요한 단계만 사용한다.

1. **배포 기준선**: 앱·플랫폼·버전·빌드 코드·운영 환경·현재 공개/심사 상태와 소스 기준을 고정한다.
2. **소스와 의존성**: 선언 버전과 실제 해석/lock 버전을 비교하고, 최신 안정 버전·변경 영향·Git 누락을 확인한다.
3. **운영 설정과 산출물**: Firebase 연결, 운영 설정, 지정 업로드 키와 실제 서명 정보, 난독화·축소 및 크래시 복원 자료를 확인한다.
4. **스토어와 공개 문서**: 정책·제출 정보·주의사항·기한, 처리방침 링크와 실제 동작의 일치, 앱·스토어·홈페이지 내용을 확인한다.
5. **기록**: 기존 배포 기록을 갱신하거나 [배포 기록 양식](references/release-record-template.md)으로 프로젝트에 버전별 기록을 남긴다. 준비 완료·업로드·심사·공개를 별도 상태로 관리한다.

보류 항목은 [선택 점검 목록](references/optional-checks.md)에 유지한다. 사용자가 선택하거나 현재 문제 해결에 직접 필요할 때만 해당 범위를 추가하며, 전체 목록을 기본 필수 조건으로 승격하지 않는다. 필수 체크리스트 안의 이벤트 수집·크래시 복원 확인은 이 보류 목록과 구별한다.

## 결과 보고

- 앱별로 핵심 미완료 항목, 실제 주의 메시지와 기한, 주요 버전 차이, 배포 기록 위치를 먼저 제시한다.
- 로컬 소스, 최종 빌드 산출물, 현재 공개 버전, 심사 중 버전의 근거를 구분한다. 하나를 확인하고 다른 상태까지 완료로 표시하지 않는다.
- 조회·빌드·테스트·제출·공개 중 실제 수행한 범위와 남은 일을 명시한다. 저장소 존재나 HEAD 일치만으로 최신 소스가 원격에 보관됐다고 단정하지 않는다.
