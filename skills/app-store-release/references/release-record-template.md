# 배포 기록 양식

프로젝트의 기존 배포 기록 위치와 형식을 우선한다. 없으면 `docs/releases/<플랫폼>-<버전>-<빌드코드>.md`를 사용한다. 여러 앱이나 플랫폼의 독립 배포를 한 행의 상태로 합치지 않는다. 아래 필드는 실제 확인값으로 채우고 모르는 값은 미확인으로 남긴다.

## 배포 기준선

| 필드 | 값 |
|---|---|
| 앱 / 플랫폼 / 스토어 앱 식별자 | |
| 표시 버전 / 빌드 코드 | |
| 환경 / variant 또는 flavor | |
| 확인 시각 / 담당 | |
| 준비 상태 | 준비 중 / 준비 완료 |
| 스토어 상태 / 기준 버전 | 미제출 / 제출됨 / 심사 중 / 승인됨 / 공개 / 거절됨 |
| 제출일 / 공개일 / 출시율 | |
| 산출물 위치 / 해시 등 식별 정보 | |

## 릴리즈 노트

사용자에게 영향을 주는 변경과 확인된 제한 사항을 적는다.

## Git 연결 — 레포지토리가 있는 경우

| 필드 | 값 / 근거 |
|---|---|
| 저장소 URL / 배포 브랜치 | |
| 배포 소스 커밋 / 기존 릴리즈 태그 | |
| 이전 버전 커밋 / 변경 범위 | |
| 관련 PR / 필요한 변경의 머지 여부 | |
| 미커밋 파일 / 미푸시 커밋 / 원격 조회 시각 | |
| 실제 빌드 소스와 기록 커밋의 일치 여부 | |

레포지토리가 없으면 이 섹션은 해당 없음으로 표시한다. Git 세부 이력을 복제하지 않고 커밋·PR 링크로 연결한다.

## 선택 항목과 남은 일

선택 점검은 보류 / 선택됨 / 실행됨으로 기록한다. 수행한 조회·빌드·테스트·제출·공개 범위와 미확인 이유를 남긴다. 매핑·심볼의 보관 위치는 안전한 참조만 기록하고 파일 내용이나 자격 증명은 넣지 않는다.
