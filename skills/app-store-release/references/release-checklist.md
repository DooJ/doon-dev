# 필수 스토어 배포 체크리스트

전체 배포 준비의 기본 항목이다. 프로젝트별 결과에는 `완료 / 조치 필요 / 미확인 / 해당 없음`과 근거를 함께 기록한다. 부분 점검 요청에서 수행하지 않은 항목은 범위 밖으로 둔다.

## Firebase Crashlytics·Analytics

- [ ] 배포 앱 식별자와 운영 Firebase 프로젝트가 일치한다.
- [ ] Crashlytics·Analytics SDK가 최종 배포 구성에 포함된다. 루트 플러그인 선언만으로 포함됐다고 판단하지 않는다.
- [ ] 운영 설정과 데이터 수집 선택에 맞게 실제 이벤트와 통제된 테스트 크래시가 수집된다. 공개 사용자에게 크래시를 유발하지 않는다.

## 라이브러리와 빌드 도구

- [ ] 현재 직접 의존성·플러그인의 선언 버전과 실제 해석 버전/lock을 확인한다.
- [ ] 공식 저장소·릴리스 자료의 최신 안정 버전과 비교하고 출처·조회일을 남긴다. 프리릴리스는 구버전 또는 다운그레이드 대상으로 단정하지 않는다.
- [ ] 주요 전이 SDK 차이가 있으면 직접 선언과 구분하고, 전체 전이 의존성을 조사하지 않았다면 범위를 명시한다.
- [ ] 코드·빌드 설정 수정이 필요한 갱신은 변경 전에 영향과 필요한 검증을 알린다. 최신 버전이라는 이유만으로 일괄 갱신하지 않는다.

## 운영 환경

- [ ] 서버 주소, Firebase 프로젝트, 광고 앱/광고 단위 ID 등 사용 중인 운영 설정을 확인한다.
- [ ] 실제 배포 variant/flavor와 운영 구성이 일치한다. 기록에는 비밀값 대신 설정 식별자 또는 안전한 참조를 남긴다.

## 난독화·축소·크래시 복원

- [ ] Android release 난독화·코드 축소·리소스 축소의 설정과 최종 번들 적용 여부를 확인한다. 다른 플랫폼에는 지원되는 동등 항목 또는 해당 없음 사유를 기록한다.
- [ ] Android R8 매핑 파일을 배포 버전·빌드 코드·산출물과 연결해 보관하고, 해당 variant의 Crashlytics 업로드 설정과 성공 근거를 확인한다.
- [ ] 네이티브 코드가 있으면 필요한 심볼, iOS는 dSYM, Flutter의 별도 Dart 난독화를 사용하면 해당 심볼 파일과 복원 경로도 확인한다. Android R8 mapping은 Dart 심볼을 대신하지 않는다.
- [ ] 통제된 동일 빌드 테스트에서 난독화 크래시가 원래 클래스·메서드·줄 번호로 복원되는지 확인한다. 업로드 성공만으로 복원 완료를 판단하지 않는다.
- [ ] Console의 최적화 점수·R8 메타데이터·실제 메시지를 확인한다. 매핑 파일의 Crashlytics 업로드와 스토어 제출 관련 설정은 서로 구분한다.

## 버전·릴리즈 노트·배포 기록

- [ ] 표시 버전과 빌드 코드(versionName/versionCode 또는 플랫폼 동등 값)를 확인한다.
- [ ] 변경 내용, 배포일, 대상 환경, 산출물 식별 정보, 심사·공개 상태를 버전별로 기록한다.
- [ ] **레포지토리가 있는 경우**, 저장소 URL·브랜치·배포 기준 커밋·관련 PR·기존 릴리즈 태그를 연결한다.
- [ ] 필요한 변경의 대상 배포 브랜치 머지 여부와 미커밋 변경·미푸시 커밋을 확인한다. 태그가 없으면 없음으로 기록하고 태그 생성은 승인된 작업 범위에서 수행한다.
- [ ] 최종 제출 소스가 원격에 보관됐는지 확인한다. 로컬 HEAD와 원격 HEAD가 같아도 미커밋 파일로 빌드했다면 완료로 처리하지 않는다.

## 스토어 정책·제출 정보·주의사항

- [ ] 앱별 정책 상태와 필수 제출 정보, 권한·데이터 수집 선언을 실제 기능·SDK와 비교한다.
- [ ] 스토어 주의 메시지의 원문 요약, 영향받는 버전, 표시된 대응 기한과 해결 근거를 기록한다.
- [ ] 현재 공개 버전과 심사 중 최신 업로드를 구분한다. 심사 전 정책 정보 미표시를 정책 통과로 해석하지 않는다.

## 개인정보 처리방침 링크

- [ ] 앱·스토어·홈페이지의 실제 처리방침 링크가 외부 사용자에게 열리고 처리방침 본문이 표시된다. HTTP 200만으로 통과시키지 않는다.
- [ ] 수집 데이터, 사용 SDK, 권한과 처리방침 내용이 일치한다. 불일치는 기록하고, 전문 법률 검토가 필요하면 별도 범위로 연결한다.
- [ ] 기존 URL과 새 URL, Console에 저장된 URL과 실제 공개 URL을 구분한다.

## 앱·스토어·홈페이지 최신화

- [ ] 기능 설명, 스크린샷, 버전 안내, 연락처가 배포 대상의 실제 동작과 일치한다.
- [ ] 최신화가 필요한 위치와 수정 결과를 각각 기록한다. 홈페이지가 없으면 해당 없음으로 표시한다.

## 업로드 키

- [ ] 앱별 설정의 지정 업로드 키와 제출 산출물의 서명 인증서 식별 정보가 일치한다.
- [ ] 분리된 키를 교체할 수 있는지 해당 스토어의 실제 키 관리 상태와 현재 공식 절차로 확인한다.
- [ ] 업로드 키와 앱 서명 키를 구별하고, 기존 사용 키·교체 가능 여부·처리 상태를 기록한다. 교체 가능성 확인을 실제 변경으로 확대하지 않는다.
- [ ] 키 파일·비밀번호·토큰을 체크리스트나 배포 기록에 넣지 않는다.
