# 단계적 전환과 폐기

## 시작 조건

- 무엇을 없애려는지, 왜 지금 필요한지, 현재 사용자와 호출부가 누구인지 확인한다. 실제 사용자가 남아 있으면 미사용 코드로 추정하지 않는다.
- 대체 구현이 중요한 기존 동작과 실패 경로를 충족하는지 확인한다. 호환성이 불확실하면 `interface-contract`로 소비자 계약을 먼저 정리한다.
- 외부 의존성 버전이 관련되면 설치된 버전과 해당 버전의 공식 문서·전환 가이드를 근거로 삼는다. 모든 소비자를 동시에 업그레이드한다고 가정하지 않는다.

## 전환 단계

1. 옛 경로와 새 경로, 소비자별 변경점, 배포 순서, 되돌리기 방법을 적는다.
2. 소비자를 점진적으로 옮기고 각 소비자의 정상·실패 경로를 확인한다. 데이터 스키마는 필요한 경우 추가 → 병행 읽기·쓰기 또는 백필 → 소비자 전환 → 제거 순서로 다룬다.
3. 검색·계측·실제 호출 증거로 옛 경로의 사용 중단을 확인한다. 관찰이 불가능하면 사용 중단을 확정하지 않고 남은 불확실성을 밝힌다.
4. 이전 버전과 롤백 경로가 더 이상 필요하지 않은 시점에만 옛 구현과 설정·문서를 제거한다. 제거 후 대표 소비자와 배포 경로를 재검증한다.

외부 사용자가 있는 공개 계약은 중단 일정과 전환 안내가 필요한지 별도로 판단한다. 코드 삭제 자체를 전환 완료로 보고하지 않는다.

## 결과

소비자별 전환 상태, 호환·롤백 범위, 옛 경로 사용 증거, 제거 여부와 미완료 단계를 보고한다.
