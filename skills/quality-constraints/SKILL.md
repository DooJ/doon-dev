# 프로젝트 품질 기준선

## 발동

여러 단계에 걸친 구현, 자율 실행 범위가 넓은 작업, 기존 검사 우회가 반복된 작업에서 사용한다. 마지막 테스트 단계에만 호출하지 않고 구현 전에 기준을 정한다.

## 절차

1. 프로젝트가 이미 사용하는 테스트, 린트, 타입 검사, 빌드, 성능 기준과 현재 결과를 확인한다. 실패 중인 기준은 새 변경의 실패와 구분한다.
2. 이번 작업이 반드시 유지할 동작과 검사, 합의된 임계치, 실행 명령, 확인 시점을 적는다. 프로젝트에 없는 수치나 도구를 임의로 강제하지 않는다.
3. 검사를 건너뛰거나 완화해야 한다면 실제 이유와 영향, 복구 조건을 드러낸다. 테스트 skip, 경고 억제, 빈 구현, 임계치 낮추기를 통과로 취급하지 않는다.
4. 구현 중에는 관련 범위부터 확인하고 완료 전에 필수 기준을 재확인한다. 기준이 바뀌면 근거와 변경 전후 결과를 기록한다.

기준을 반복해서 참조해야 하는 프로젝트에만 프로젝트 원본 문서에 간결하게 남긴다. 문서나 CI 설정을 만드는 것이 이 스킬의 기본 산출물은 아니다.

## 결과

기존 기준선, 이번 필수 기준, 실제 실행 결과, 예외와 미검증 범위를 보고한다.
